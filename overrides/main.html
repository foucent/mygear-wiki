This override drops that suffix on the frontmatter branch only. Why: the house convention is that a frontmatter `title:` is a *complete* SEO title with the brand already in it — the /gear/ product pages and two guide articles write theirs as "… Review, Price & Specs | MyGear.Top", and /order/, /FAQ/, /updates/ and /guide/ follow the same shape. Passing those through Material unmodified would render "… | MyGear.Top - MyGear.Top". The `elif` branch is deliberately left as Material wrote it: a page with no frontmatter title is titled from its nav label, which the short labels in mkdocs.yml make lossy, so those pages want the site name added. Neither branch touches the nav label, the H1, or the search index title — the nav comes from mkdocs.yml and the other two from the H1, all verified. -#} {% block htmltitle %} {%- if page.meta and page.meta.title -%} {{ page.meta.title }} {%- elif page.title and not page.is_homepage -%} {{ page.title | striptags }} - {{ config.site_name }} {%- else -%} {{ config.site_name }} {%- endif -%} {% endblock %} {#- Open Graph / Twitter cards. The site had none, so every share of a page — WhatsApp, Reddit, a forum — went out as a bare link with no title, no summary and no picture. WhatsApp is where most of this shop's traffic is asked to land, which made it the one place the omission actually cost something. og:title / og:description / og:url are derived per page and are always correct, so they are emitted everywhere. og:image is not derivable: a landscape card has to be built for the page it represents (see docs/images/og/), so it is opt-in through an `og_image:` frontmatter key rather than a site-wide default that would put a Viscaria photo on the /pre-owned/ share. `page.canonical_url` is what makes it absolute, which the scrapers require.
